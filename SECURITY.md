# Security and reporting

Author: Sandeep Belgavi

Use private GitHub vulnerability reporting for vulnerabilities. Do not put credentials, customer records or exploit details in public issues. This educational preview has no security certification or support SLA.

The runtime is recommendation-only. Its CLI-provided scope, budget and approval are demonstrations, not production identity or billing controls. A service embedding it must derive authorization from authenticated server state, enforce durable quotas and keep business effects behind a separate executor.

Live mode sends selected input fields to TypeSafe and can incur charges. Use minimized authorized data and a scoped secret-management process. The API adapter uses a fixed HTTPS endpoint, bounded bodies, a deadline and no automatic retries. No key is included in the repository.

Model outputs and source documents remain untrusted. Valid types and passing fixture tests do not prove correct judgment, fairness, jailbreak resistance or fraud-prevention effectiveness. Review README and the source tests before use.
